# FreeToken via APIs Ollama e OpenAI

Este Compose executa o `ft daemon` e um proxy leve na porta interna `11434`. O proxy oferece `/api/tags`, `/api/show`, `/api/ps`, `/api/version`, `/api/chat` e `/api/generate` para o Open WebUI. Ele inicia o modelo pedido via daemon, aguarda `/health` indicar `status: ok` e `maintenance: serving` antes de enviar o chat, e para o engine depois de cinco minutos sem requisições. O daemon e o `ft serve` não publicam portas no host.

O `ENTRYPOINT` da imagem executa `ft bench bw` na primeira inicialização de `ft daemon` ou `ft serve` com uma GPU, antes de abrir a API. O perfil gerado pelo FreeToken e um indicador por UUID da GPU ficam no volume `benchbw_cache`, então reinicializações não repetem o benchmark. O indicador só é criado após o comando terminar com sucesso e gravar um perfil; se falhar, o servidor ainda inicia e o benchmark é tentado novamente na próxima inicialização. O volume aceita tanto o perfil atual `benchbw/<UUID>.json` quanto o formato antigo `benchbw.json`. O perfil permite que `--moe-strategy auto` escolha `hybrid` quando a medição o recomenda; em outros casos, a escolha continua sendo `offload`. Para refazer a calibração, remova o indicador em `autobench/<UUID>.done` do volume ou recrie esse volume. Consulte a [documentação de modelos](https://github.com/FlashML-org/FreeToken/blob/main/docs/models.md) e a [referência do benchmark](https://github.com/FlashML-org/FreeToken/blob/main/docs/cli.md#ft-bench-bw).

O benchmark roda em primeiro plano: o daemon ou servidor só inicia depois de sua conclusão. Os logs mostram o relatório do FreeToken e um resumo por formato com a recomendação (`hybrid` ou `offload`) e as larguras de banda medidas. Em reinicializações, o resumo é lido do perfil persistido.

Edite [models.json](models.json) para definir os modelos visíveis. Cada entrada contém `name` (o alias exposto ao cliente), `model` (ID Hugging Face ou caminho no container do daemon) e `args` opcionais para `ft serve`. Para caminhos locais, monte o diretório de modelos no serviço `daemon` e use o caminho dentro desse container. O catálogo é lido ao iniciar o proxy; reinicie-o após editar o arquivo. A primeira entrada usa `google/gemma-4-E2B`, presente no exemplo original deste repositório.

Crie a rede compartilhada `proxy` se ainda não existir e suba os serviços com `docker compose -f freetoken/docker-compose.yml up -d --build`. O serviço `freetoken-proxy` ingressa nessa rede e pode ser alcançado pelo Open WebUI em `http://freetoken-proxy:11434`. O Compose em `ollama/` configura `OLLAMA_BASE_URLS` com o Ollama atual e o novo proxy. Em instalações existentes, o Open WebUI pode manter no banco as URLs alteradas pelo painel; nesse caso, adicione a URL em **Admin → Connections → Ollama**. Não é necessário redefinir as outras configurações persistidas.

O proxy não carrega modelos ao subir. A primeira requisição a um modelo inicia o engine e aguarda a carga terminar antes de enviar o chat; não é preciso reenviar a mensagem. O mesmo vale após o prazo idle descarregar o modelo. O Open WebUI usa timeout de 30 minutos para cobrir cargas frias longas.

Para integrações OpenAI dentro da rede Docker `proxy`, use `http://freetoken-proxy:11434/v1` como base URL; aplicações no próprio host podem usar `http://127.0.0.1:11435/v1` (porta configurável por `FT_PROXY_PORT`). Use um `name` de `models.json` como ID do modelo. O proxy oferece `GET /v1/models`, `GET /v1/models/{id}`, `POST /v1/chat/completions`, `POST /v1/completions` e `POST /v1/responses`. A listagem não carrega o engine. As três rotas de inferência iniciam o modelo quando necessário, esperam a prontidão e preservam o JSON ou SSE do FreeToken, com o ID retornado ajustado para o alias do catálogo. Clientes que exigem uma chave OpenAI podem usar um valor fictício; o proxy não verifica essa chave. A porta do host escuta apenas em `127.0.0.1`, enquanto o daemon e o `ft serve` permanecem na rede interna. Ajuste o timeout do cliente para cobrir a carga fria, cujo limite no proxy é `FT_START_TIMEOUT_SECONDS`.

`FT_IDLE_SECONDS` (padrão 300) e `FT_START_TIMEOUT_SECONDS` (padrão 900) podem ser ajustados via ambiente do Compose. `keep_alive` em `/api/chat`, `/api/generate` e nas rotas OpenAI de inferência aceita segundos ou durações como `10m`; `0` descarrega após a resposta, inclusive após o fim de um stream, e valor negativo mantém o modelo carregado. O campo é retirado antes do envio ao FreeToken. Um generate sem prompt com `keep_alive: 0` descarrega o modelo, como no Ollama. O daemon aceita `FREETOKEN_DAEMON_TOKEN`; o Compose usa o mesmo valor no proxy e um token local padrão quando a variável não é definida.

O daemon controla um engine por vez. Requisições a outro modelo enquanto um está ativo retornam HTTP 409. `/api/tags` lista o catálogo sem iniciar o engine; `/api/ps` mostra o modelo ativo apenas quando `/health` confirma que está pronto, e retorna uma lista vazia durante o carregamento. O campo `expires_at` sempre contém uma data válida para o Open WebUI, inclusive com `keep_alive` negativo. Os metadados Ollama que não existem no FreeToken, como tamanho em disco e formato GGUF, não são inventados: o tamanho é `0` e o formato é `freetoken`. O `digest` é uma identidade estável derivada do ID do catálogo, não um hash dos pesos.

O proxy cobre texto e chamadas de ferramenta nos chats, além de completions simples. Recursos de gerenciamento de modelos do Ollama, embeddings, geração de imagens e ajustes de contexto por requisição não fazem parte desta versão. Configure os argumentos de contexto e runtime em `models.json` para o `ft serve`. A URL de inferência do FreeToken permanece interna à rede Docker.

Para rodar os testes do proxy com Python 3.12: instale `proxy/requirements-dev.txt` e execute `pytest -q freetoken/proxy/test_app.py`. Eles usam servidores simulados e não exigem GPU.

Para testar o auto bench sem GPU, execute `python3 freetoken/test_daemon_entrypoint.py`; o teste simula `nvidia-smi` e `ft`.
